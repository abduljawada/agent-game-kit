# Assets

Use what exists before making anything new. Order of preference:

1. **Packs already in the repo** (`assets/kenney/`, CC0).
2. **More Kenney packs** from the local archive: `assets/kenney/CATALOG.md` lists all ~250,
   `scripts/assets/kenney.py add "<Category>/<Pack>"` extracts one (only engine-ready files).
3. **Synty POLYGON packs** (licensed, local only): `scripts/assets/synty.py list` / `add <Pack>`
   copies them into `assets/local/synty/` with textures wired up on import.
4. **New 3D models** made in Blender through the Blender MCP server, exported as `.glb` to
   `assets/models/`.
5. **New 2D art or sound** made or generated by hand: follow the `create-game-assets` skill
   (brief → one approved hero asset → families → normalise → check → record provenance).

## Layout and licences

| Folder | Source | Licence | In git? |
|---|---|---|---|
| `kenney/<category>-<pack>/` | Kenney All-in-1 archive | CC0 (`License.txt` in each pack) | yes |
| `models/`, `sprites/`, `audio/` | made for this game | yours | yes |
| `local/synty/<Pack>/` | Synty Studios packs | Synty licence: use in games, **no redistribution** | **no** (`assets/local/` is git-ignored) |
| `local/sources.cfg` | paths to the Kenney zip and Synty folder on this machine | – | no |

**Never copy Synty files outside `assets/local/`, attach them anywhere, or commit them.**
A game built with them can ship them inside its exported build; the source files stay private.
A fresh clone has no `assets/local/`; anything that depends on Synty must say so and be
skipped by tests when the files are missing.

## Seeing assets (required before using them)

- 3D: `scripts/assets/preview.sh res://assets/kenney/3d-platformer-kit` renders every model as
  labelled pages in `.godot/previews/<folder>/page_NN.png`. Open the pages and check
  silhouettes, textures and orientation.
- 2D: `python3 .agents/skills/create-game-assets/scripts/build_preview_sheet.py <pngs> --out sheet.png`
  and `asset_report.py` for size/alpha/colour checks.
- In game: `scripts/record.sh` with an input timeline (see AGENTS.md).
